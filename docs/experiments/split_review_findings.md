25 reproduced findings from three independent adversaries (leakage / statistics / integration lenses). Every finding below was
reproduced by running code; the `REPRODUCTION` field is an observation, not a hypothesis.

## F01 [FATAL] `gold_standard/textsig.py`:54

**Claim.** The template relation is computed over only the first 2,500 characters of cleaned text, and invariant I7 - the architecture's "independent" backstop - re-derives from the same truncated cache. The leakage guarantee therefore covers a prefix, not a posting. 98 posting pairs in the SHIPPED group map are already template pairs by the stated rule (full cleaned-text Jaccard >= TAU_BUILD) and are NOT grouped, so they are free to straddle train/test, and no invariant can see it.

**Reproduction.** REAL CORPUS (no tampering, shipped artifacts): recomputing shingles over the full cleaned description for all 18,667 pool postings finds 11,272 pairs at full_J >= 0.30; 11,171 are in the same leakage group and 101 are in DIFFERENT groups. Recomputing those 101 pairs' TRUNCATED Jaccard from the shipped shingles.parquet: 98 are below 0.30 (median 0.050; 25 of them exactly 0.000) - i.e. missed because of the 2,500-char cut. Worst case: u-4e564dfcf7df2563 (company 'ITALDESIGN', 6,300 chars, group g:u-4e564dfcf7df2563) vs u-addb057dcdb16fc6 (company 'ITALDESIGN GIUGIARO', 4,978 chars, group g:u-addb057dcdb16fc6): full_J=0.7374, trunc_J=0.2814 - the same employer and a 74%-identical template in two different groups, both in_pool, with 58 and 47 sampleable (en/id, 20-300 char) sentences each. Also u-06bd527a264a3749 ('LTIMindtree') vs u-0cbab9a792c7f2c6 ('LTM Limited'): full_J=0.4873, trunc_J=0.0496, different groups. END-TO-END: planted 12 pairs (distinct employers, own template, shared block starting after char 2,600) -> 0/12 grouped, 0 rows in template_pairs.parquet; at seed 42 two pairs and at seed 3 four pairs land train/test; run_split WROTE the split with I2/I3/I4/I5/I6/I7/I8 all "passed", manifest invariants.max_cross_part_jaccard = 0.1573 and group_layer.claim_wording = "no employer ... and no template cluster at cleaned-text Jaccard >= 0.3 straddles any two parts" while the straddling pairs measure 0.375 on full text. The blind spot bites at ordinary lengths: a pair with a 2,600-char unique prefix and a shared block giving 4,862 total chars (below the real q0.75 of 5,377) measures full_J=0.4032 / first-2500_J=0.0166. Exposure on real data: 69.0% of pool postings exceed 2,500 cleaned chars (median 3,705, q0.90 7,004, q0.99 10,952); mean per-posting signature coverage is 69.4% and 31.2% of postings have <50% of their signature compared; 46.9% of pool SENTENCES start at or after char 2,500, i.e. the text annotators will label is mostly outside the region the leakage layer compares; 33.3M characters of description are never compared.

**Suggested fix.** Shingle the FULL cleaned text in the leakage layer: pass max_chars=None (or a value past q0.99) in gold_standard/textsig.shingles_from_clean_text when called from groups.py/build_pool's leakage sidecar, keeping SHINGLE_MAX_CHARS=2500 only where parity with governance.ladder.minhash_near_dups is actually required. Full-text cost measured here: 432 s for the whole pool, mean 548 shingles per posting - affordable. Until that is done, rewrite leakage_groups_manifest.claim_wording and split.manifest.limitations to say "over the first 2,500 characters of cleaned text", and add a test whose planted template bridge lives past char 2,500 (the current I7 positive control uses ~120-char strings, so it cannot fail for this reason).

## F02 [FATAL] `gold_standard/seal.py`:187

**Claim.** `score_on_test` builds its scoring units by iterating `gold.items()`, so every sealed test sentence that carries NO gold span is silently dropped from the denominator. All false positives on gold-empty sentences vanish, micro precision (hence micro-F1, the bootstrap CI and `n_test_sentences`) is computed only over gold-bearing sentences. For a 5-tag span task on natural job postings — where the project's own guideline has NON_RELEVANT / has_5tag=TIDAK categories — gold-empty test sentences are the normal case, not a corner case.

**Reproduction.** Sealed test = 4 sentences (s1..s4); gold = one ACCEPT span on s1; predictions = the correct span on s1 plus three spurious spans on s2/s3/s4. Truth: tp=1, n_gold=1, n_pred=4 -> precision 0.25, recall 1.0, F1 0.40. Observed output: `micro = {'tp': 1, 'n_gold': 1, 'n_pred': 1, 'precision': 1.0, 'recall': 1.0, 'f1': 1.0}` and `n_test_sentences: 1` against a sealed n of 4. A model that hallucinates on 3 of 4 test sentences is reported at F1 1.000.

**Suggested fix.** Build `contribs` over the sealed sentence_id list read from `test_blind.parquet` (which `materialise_labels` already loads), defaulting `gold.get(sid, set())`, so gold-empty sentences contribute (0, 0, len(pred)). Report `n_test_sentences` as the sealed n and add `n_gold_bearing_sentences` separately. The same change is needed in the per-tag loop at line 192 and it fixes the bootstrap population at the same time.

## F05 [SERIOUS] `gold_standard/groups.py`:95

## F08 [SERIOUS] `gold_standard/split.py`:161

**Claim.** `axis_targets` calls `largest_remainder` independently for every axis VALUE, so each value rounds in isolation and the per-part target column does not close to the part size. The targets are arithmetically unmeetable even in principle, which contaminates every reported per-value `delta`, every `tv_distance`, and the headline `allocation_cost.final_weighted_abs_deviation`. In the soft regimes it is worse: targets are apportioned over `work` (1,200 minus dropped) while 27 further sentences are then excluded, so the whole column is offset.

**Reproduction.** Real CONFIG_A grouped_random (exact 720/240/240, zero exclusions): 13 of 27 (axis, part) combinations have a target column that does not sum to the part size — `marginals.country_iso.dev.target` sums to 243 for a 240-row part, `country_iso.test.target` sums to 237, `quarter.train.target` sums to 721 for 720, `occupation_group.dev` 243, `length_band.dev` 241. Real temporal: ALL 27 combinations are off — `stratum.train.target` sums to 735 against a 719-row part, `site.dev` 246 vs 240, `occupation_group.test` 217 vs 212. The emitted `final_weighted_abs_deviation` is 362 (grouped_random) and 2755 (temporal), so a large part of the reported 'imbalance' is rounding residue plus regime-structural impossibilities (e.g. `marginals.quarter.test` asks for 52 sentences of 2026Q1 in a test set that is DEFINED as the late period, and reports delta -52).

**Suggested fix.** Apportion with a two-stage largest-remainder: first the part totals, then, inside each part, distribute that part's quota across axis values so each column sums exactly to the part size. Apportion over the ASSIGNABLE rows (df minus excluded minus dropped), not over `work`. For the temporal regime, do not emit per-part targets for `quarter` / `date`-derived axes at all, or mark them `not_applicable: regime partitions on this axis`.

## F10 [SERIOUS] `gold_standard/split_assert.py`:307

## F12 [SERIOUS] `gold_standard/split.py`:246

# Adversary verdicts

## Lens: leakage

The leakage guarantee is broken in one load-bearing place and soft in three others, and the break is already present in the artifacts on disk rather than being merely constructible. The architecture's whole answer to "similar template is not transitive" is (a) union-find over verified shingle pairs and (b) I7, an all-pairs re-derivation advertised as independent of (a). Both read the same 2,500-character prefix, so they share a single blind spot: on the real pool, 101 posting pairs are template pairs by the stated rule (full cleaned-text Jaccard >= 0.30) and sit in different leakage groups, 98 of them because of the truncation (median truncated Jaccard 0.050; 25 pairs exactly 0.000). The worst is a same-employer pair, ITALDESIGN / ITALDESIGN GIUGIARO at full_J 0.737, both drawable into main_1200 with ~50 eligible sentences each. End to end, 12 planted pairs of this shape straddle train/test over several seeds with all seventeen invariants green and the manifest asserting max_cross_part_jaccard 0.1573 and "no template cluster at cleaned-text Jaccard >= 0.3 straddles any two parts". Because main_1200 has not been drawn yet, nothing has leaked - so this is fixable before it costs anything, and the fix is cheap: a full-text pass over the whole pool took 432 s. The three softer defects are the <3-char loose-residual rule (230 real postings silently lose the loose relation, including the "IT Group Pte Ltd / IT Group Indonesia / IT Thailand" class the rule exists for), I7 degrading to n_pairs_compared=0 / max=0.0 when the shingle cache does not cover the sample, and the build_pool shingle sidecar being consumed with no staleness check even though build_pool writes a fingerprint for it that nothing reads. Separately, the primary regime cannot absorb a single excluded sentence or an under-filled draw: P2 raises with a message blaming the group map, which makes pilot_group / practice_group / date_unparseable dead reasons in grouped_random. ATTACKED AND HELD (residual doubts rather than findings): the empty-employer question the task flags as a silent disaster is implemented the right way - "", None and NaN are all treated as missing and never collapse (417 real company-less pool postings -> 386 distinct groups; a pure-function probe on '', None and NaN each yields 4 distinct components, and groupby's dropna plus the != "" filter covers all three), and those postings are forced to train by base_forced with I9 at 1.0. Case, double-space, NBSP, trailing-period and NFC-vs-NFD company-name variants are all caught (exact hash for case/whitespace, loose hash for punctuation and NFKC). A sampled posting absent from the group table is refused by load_inputs, and a stale group map is refused by draw_sample. The temporal regime held in every run: per-stratum early-max < cut <= late-min, no group spanning a cut, straddlers dropped with the right reason, and an all-late group with an unverifiable employer excluded rather than placed. edge_provenance is correct on real data (0 multi-posting groups mislabelled "singleton"). Determinism held (identical assignment_sha256 at a repeated seed). Two latent hazards I could not reach through the pipeline, so I am not reporting them as findings: i9_dev_test_verifiable passes when employer_known is NaN or the string "False" (astype(bool) -> True) and i2_group_disjoint passes vacuously when group_id is NaN (_by_part uses .dropna()); both are currently unreachable only because load_inputs raises on a NaN group_id first, so a dtype change in the join would open them. I did not test seal.py or the registry/power machinery - out of scope for this attack.

## Lens: statistics

The leakage machinery is genuinely sound and the determinism claim holds. The STATISTICAL REPORTING does not: one fatal scoring bug, and the manifest's target/achieved discipline fails in the exact way the project was burned before.

WHAT SURVIVED ATTACK. Seeded determinism is real — two independent fixture builds produce byte-identical data artifacts (34 files compared; only `created_utc` leaves differ in the JSONs), and the real-data grouped_random `assignment_sha256` and `assignment.parquet` bytes match across runs. The real 1,200 draw honours `group_cap=2` exactly (1,088 weight-1 / 56 weight-2 groups) and lands on 540/240/420 per `STRATUM_QUOTA`; the parity proof then hits 720/240/240 exactly with zero exclusions. Every arithmetic figure I recomputed by hand is right: ci_width(240)=0.1086, ci_width(108)=0.162, mde(240)=0.0549, the 120-span threshold (96.04 x 1.18 = 113.3), the CONFIG_A2 slope (0.0073 F1 for 120 sentences, CI 0.109 -> 0.089), and `achieved_stratum_resolution['L0'] = 0.6633`, which I reproduced independently. The registry gate, fail-closed write, the real-corpus group-layer numbers, and `train_720.parquet` (exactly 120, group-atomic) all check out.

WHAT DID NOT. (1) `seal.score_on_test` reports F1 1.000 for a model with three false positives out of four predictions, because sealed test sentences with no gold span are dropped from the denominator — in a 5-tag span task with an explicit NON_RELEVANT category, that is the dominant case, so every headline test number this layer will ever publish is inflated. (2) For temporal and cross_country the manifest's `target` IS the achieved assignment: real-data temporal reports `targets.test = 212` with `delta: 0`, `exact_sizes_met: true` and `unmet_targets: []`, and the registered 240 appears nowhere in the sizes block; cross_country/SG reports test 116 the same way. (3) I16, the invariant written specifically to make this a write-time error, is a key-presence check that cannot fire. (4) Per-axis targets do not sum to the part size — 13 of 27 combos on the exact primary split, all 27 on temporal — so the published `delta`, `tv_distance` and `final_weighted_abs_deviation` are contaminated, and the temporal manifest prints unmeetable targets (52 sentences of 2026Q1 in the late-period test). (5) The temporal confound report omits occupation_group, whose early-vs-late TV is 0.4741 with 391/959 early versus 0/212 late UNRESOLVED — the drift claim's biggest confound is absent from the artifact built to disclose confounds. (6) The cross-country group rule only sees sampled postings: 19 SG-touching and 20 US-touching groups bridge the boundary, with a named employer hash on both sides.

Nothing is committed, so all of this is fixable before `main_1200` is drawn for real.

RESIDUAL DOUBTS I could not turn into findings. `DESIGN_EFFECT = 1.18` is a bare constant with no `assumed/measured/source` structure; it is defensible as a span-within-sentence effect at 1.6 spans/sentence (rho 0.30) and errs conservative, so I am not calling it wrong — but the group-level clustering it is claimed to capture is at most 1.093 in the realised sample. `occupation_stratified` is `true` when the UNRESOLVED share is below an unregistered 0.5 threshold, which would call 49% UNRESOLVED 'stratified'. `i11_oversize_groups` uses the circular soft target, so a very small external test could make a weight-2 group trip the 0.25 share and refuse the write — I did not construct a corpus small enough to see it. `i7_direct_pairwise_jaccard` silently skips postings with an empty shingle set (`continue`), so description-less postings are never checked for template similarity and that is not recorded in the manifest; I could not construct a real case where it mattered. The 'test set stays sealed, selection happens on dev only' claim is unfalsifiable beyond this layer because no model-selection or training code exists in the repo yet, and `test_blind.parquet` carries full sentence text in the same directory as train/dev with no access control — which `seal.py` correctly describes as auditability, not impossibility. Finally, the sample's ASEAN local-language share comes out 0.0 against the configured `MIN_LOCAL_LANG_SHARE['asean'] = 0.30`; `sample.py:_write` does warn on this, so it is handled, but it means the language stratification the proposal asks for is unmet for one of three strata and only visible in stdout and the sample manifest, never in any split manifest.
